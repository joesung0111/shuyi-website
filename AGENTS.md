# Project workflow

- After making a requested change in this project, commit it and push only to the production branch `main`. Never push to or deploy the preview/test branch or service unless the user explicitly requests it.
- If work is split across multiple branches or worktrees for the same request, integrate the changes into one production `main` commit before pushing.
- Keep unrelated user changes out of the commit. Report the branch and commit after pushing, and distinguish a push from deployment or public-site verification.
