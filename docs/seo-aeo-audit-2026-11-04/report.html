舒逸官網 SEO 與 AEO 驗收報告

檢查日期 2026 年 11 月 4 日｜範圍 正式站 Sitemap 22 個頁面｜基準本機 commit 851df82

首要處理 公開 API 未登入可讀草稿；文章列表在載入時也會短暫顯示草稿預設卡片。工作室頁的預約文案已過期。以上均已實際確認。

已完成的檢查

22 頁 HTTP、初始 HTML 的 Title、description、canonical、H1、JSON-LD 語法及重複值檢查無異常；robots 和 Sitemap 的 GET / HEAD 均為 200；掃描初始 HTML 中 36 個不同 HTTP 連結。16 篇文章的文字、來源與醫療界線已閱讀，詳見逐頁說明及 JSON。瀏覽器實測 FAQ 展開及收合、文章影片分類及工作室／預約頁。

6 個 CDC / OSHA 來源在本環境回應 403，需要人工確認，不等同死連結。文章返回 #journal-return 使用 JavaScript 和 sessionStorage，靜態檢查沒有對應 id，不能直接視為失效。

優先調整工作單

P0-01 未登入 API 可讀取草稿

證據：GET /api/content 未登入回傳 18 筆，其中 2 筆 draft；status=published 回傳 16 筆。server.js 對 GET /api/content 在 requireAuth 前執行。

影響：未發布資料可能被公開，搜尋引擎或其他系統可能讀取。

建議：公開讀取僅回傳 published；管理後台取得全部內容必須通過現有登入驗證。保留後台正常操作及公開已發布清單。

驗收：未登入無法取得草稿；已登入管理可讀取草稿；published API、Journal SSR、sitemap 行為不退化。

P1-01 文章列表短暫顯示草稿預設卡片

證據：瀏覽器實測初次顯示 DRAFT 卡片，隨後切換為 16 篇 published；content.js 先設定包含草稿的 fallback，app.js 立即 renderContent，API 失敗時 fallback 保持。

影響：訪客可能看見未發布內容與失效網址，且初始 SSR 與執行後不一致。

建議：保留伺服器產生的 published 清單，API 成功才更新，失敗時保留現有清單；移除公開環境草稿 fallback。

驗收：慢網路與 API 失敗下無草稿或 404 卡片，篩選及回到列表位置正常。

P1-02 工作室頁預約訊息已過期

證據：/studio/ 顯示「正式預約方式將在開放時公布」；/booking/ 已提供 booking.sy-body.com 入口。

影響：訪客與搜尋系統看到相互衝突的營業資訊。

建議：以已公開的預約流程更新文字並連往 /booking/；地址、營業時間僅在業主確認後更新。

驗收：工作室、服務與預約頁一致，連結可用，不編造地址。

P1-03 草稿靜態路由 HEAD 與 GET 不一致

證據：/journal/activate-after-sitting/ 與 /journal/studio-in-progress/ GET 404、HEAD 200；不代表所有未知路由相同。

影響：透過 HEAD 檢查的工具可能錯誤認定草稿頁可存取。

建議：追查靜態檔與 Journal 路由對 HEAD 的處理，讓未發布內容 GET 與 HEAD 都是 404；不得導回首頁。

驗收：草稿 GET、HEAD 均 404；已發布文章 GET、HEAD 200；sitemap 不變。

P1-04 產後服務資訊及安全界線待專業確認

證據：/offerings/ 的產後骨盆調理提及 3–6 個月且明示尚待專業確認；/services/ 表示曾手術部位不提供。

影響：讀者仍無法判斷產後、剖腹產或手術後是否可預約，時程涉及個人健康。

建議：請業主確認實際政策，必要時由產後或醫療專業審閱；移除未經確認的時程並明確說明手術限制及詢問方式。

驗收：跨頁政策一致、無復位或療效承諾；專業審閱僅在真實完成時標示。

P2-01 Journal 初始與執行後標題不同

證據：初始 H1「給生活一點新的情報」，執行 app.js 後為「讓舒適的身體習以為常」；導覽內容亦由 JS 插入。

影響：不同讀取方式取得的資訊不一致，品牌及主題訊號分散。

建議：確認最終文案，將主標與關鍵導覽放進初始 HTML，動畫逐字顯示仍保留可讀完整文字。

驗收：關閉 JS 與啟用 JS 均有一致主標和完整文字，畫面設計保留。

P2-02 文章健康內容及來源逐項核對

證據：16 篇均有內容界線及審閱狀態；CDC 4 個及 OSHA 2 個來源在本環境 GET 回 403，無法判斷是否失效；4 篇明示沒有引用研究卻仍顯示參考資料連結檢視日期。

影響：來源支持範圍及可用性未完全確認，日期用詞可能誤導。

建議：逐項核對每個事實與原始來源及其適用範圍；403 使用一般瀏覽器或官方查詢重驗，不能直接判死鏈；無來源文章不要顯示來源連結檢視日期；需要專業審閱的文章等待真實審稿。

驗收：每篇有清楚內容性質和界線，來源能支持相應敘述，審閱資訊真實。

P2-03 位置與聯絡資訊不足

證據：/studio/ 的地址和營業時間均為準備中；頁內缺少明確預約 CTA。

影響：使用者難以判斷地點及安排，地方查詢欠缺可確認資訊。

建議：請業主確認可公開地址、服務地區、營業時段、聯絡方式；只發布已確認資料，並視資料完整度評估 LocalBusiness。

驗收：公開資料與預約平台一致；不得捏造地址或結構化資料。

P2-04 文章結構與站內連結可提升

證據：16 篇內容均有一個 H1，但正文透過 bodyHtml 轉成段落，未以 H2 分出答案、步驟及警訊；相關內容主要統一指向服務與預約。

影響：較長文章的可掃讀性、主題導航與相關文章發現可改善。

建議：依文章真實內容增加具描述性的分段標題、明確直接的回答及相關文章連結；避免大量重複或填充。

驗收：初始 HTML 存在標題及正文，保持原有語意與事實，不強加 FAQ Schema。

P2-05 圖片與分享素材檢查

證據：HTML img 均有 alt 屬性；15 篇使用 Unsplash 圖，頁面共同 OG 圖多為品牌圖片。是否每張圖與 alt 完全相符及圖片授權未完成人工確認。

影響：圖片敘述不準可能降低可及性，遠端圖片不可用影響分享與呈現。

建議：逐張查看圖片與 alt，裝飾圖空 alt；確認來源權利與載入可靠性，測量尺寸與 LCP 後決定處理。

驗收：alt 符合圖像和情境、圖片可載入；不得堆砌關鍵字。

P2-06 搜尋和轉換缺少帳號層驗證

證據：HTML 自動檢查無法證明 Google/Bing 收錄、查詢、排名、AI 引用或 GA4 事件。

影響：無法知道實際搜尋與預約成效。

建議：取得 GSC 與 Bing 已驗證資源及 GA4 資料流後檢查索引、sitemap、查詢、核心網頁指標、預約 CTA；確認網站與預約平台跨網域需求及同意設定。

驗收：保留截圖或報表日期、屬性、指標及驗證結果，未連線時標記未驗證。

仍無法確認的項目

  • Google Search Console、Bing、GA4 的收錄、搜尋與轉換數據；搜尋結果或 AI 引用不能由 HTML 推定。
  • 所有圖片的視覺內容與 alt 逐張比對、全部手機尺寸、全互動及登入後預約流程。
  • 醫療或產後專業審閱、地址、營業時間及服務政策須由合適人員確認。
  • 個別參考來源的 403 及原文是否直接支持每一句陳述仍要人工核查。
