# 分析儀表板改善與使用說明

日期：2026-11-06。入口：https://sy-body.com/manage-center/analytics/ 。本次僅修改管理端查詢與呈現，不增加公開網站追蹤請求、第三方腳本或背景輪詢。

## 功能調整

| 功能 | 調整前 | 調整後 |
| --- | --- | --- |
| 趨勢數量 | 原生 title 只有單個數值，不容易比較 | 游標移入或點選時間區段，顯示日期／時段及全部數列；方向鍵可切換時間；提示使用已載入資料，沒有額外查詢 |
| 管理者 | 有總覽數字，趨勢缺少獨立數列 | 金色管理者請求數列、圖例及總覽卡片；圖例可切換顯示。總請求已含管理者與爬蟲，不能重複相加 |
| SERVER LOG | OFFSET 分頁與一直附加列，資料越看越多 | Cursor Pagination（游標分頁）以時間與 ID 接續讀取；每頁固定 50 筆並替換畫面，提供上一頁、下一頁、符合條件總數與重新查詢 |
| 新請求進站 | 可能讓不同頁次的列往後移動 | 用查詢開始時最大 ID 固定截止點，新資料等重新查詢才納入。這是截止快照，保存期限清理仍可能移除舊列 |
| CSV | 沒有匯出 | 匯出符合日期與篩選的整個快照（不限目前頁），固定遮罩 IP，超限時明確拒絕，不默默只截取前幾筆 |
| 重要互動 | 只有名稱與次數，不易理解 | 改名「關鍵互動／轉換」，說明每個事件、次數與 Session 的差異；按需展開來源頁面、最近活動與瀏覽路徑 |

## 如何使用

1. 選擇今天、昨天、7 天、30 天或自訂日期；趨勢時間依畫面顯示的 UTC offset 計算。空白時段也可查到 0。
2. 滑過任一柱形或點擊時間區段查看數量；手機可點選，鍵盤可使用左右方向鍵、Home、End、Escape。
3. 點圖例可隱藏／顯示數列，至少保留一項；所有顯示切換均在瀏覽器完成。
4. SERVER LOG 可依日期時間、IP、端點、狀態碼、訪客分類及頁面／API／靜態類型篩選。單次最多 31 天；更長的保存資料需分段日期查詢。
5. 下一頁每次只查 50 筆，沒有只保留前 50 筆的限制。快照有效 30 分鐘，部署重啟也會失效；過期或改動條件時按「重新查詢」。
6. CSV 會下載本次篩選的整個截止快照，保持 UTC 時間與遮罩 IP。原本勾選畫面完整 IP 也不會改變 CSV 的遮罩規則。
7. 點互動事件的「查看來源與明細」，最多列出前 20 個來源頁面與最近 25 筆活動；可接著查看該 Session 路徑。

## 資安與流量控制

- 新增的所有查詢與下載 API 都先驗證既有管理員 Session；Cookie／Bearer Token 沒有放進下載網址。
- 游標由 HMAC 簽章（驗證游標沒有遭到竄改）保護，綁定篩選條件並設 30 分鐘效期。簽章密鑰只在程序記憶體，不寫入前端；重新部署後需重新查詢。
- CSV 每次最多 10,000 筆且保守預估不超過 10 MiB；超過時回 413，請縮小日期或篩選。前端也檢查實際下載大小，超過就取消，不儲存不完整檔案。
- 匯出每個管理登入每分鐘最多兩次、一次一份；伺服器全域最多兩份同時匯出，60 秒逾時取消。按每 200 筆串流寫出並處理 backpressure（等待下載端接收），避免在伺服器一次組出整份檔案。
- CSV Injection（試算表公式注入）防護：對可能被當成公式的文字加上文字前綴，並正確跳脫引號、逗號與換行。
- 管理查詢每登入每分鐘最多 120 次；搜尋暫停 600ms 後才查詢，過時查詢會取消。退出登入會停止待處理查詢及下載。
- 首次儀表板資料由原本 7 個分析查詢合併為 3 個（摘要、訪客、請求頁）；IP 診斷僅展開時查一次。摘要在伺服器短暫快取 5 秒，最多保留 50 組條件，不在 CDN 公開快取。
- 滑過圖表、鍵盤切換與圖例開關都不會送出 HTTP 請求；事件明細只在點擊後查詢。沒有自動更新或背景預先下載全部資料。
- 新增 analytics_events(event_name, occurred_at) 索引；日誌日期查詢沿用時間索引。新模組仍受公開資源允許清單保護，不能透過網址下載。

## 統計定義與限制

- 一般訪客／頁面瀏覽的定義延續既有收集方式，排除已標記的管理者；匿名 Visitor ID 與 Session 不等於實際人數。
- 管理者只代表請求當時有有效管理登入，登出或換瀏覽器無法判定為同一位管理者。
- 請求總數包含管理者與爬蟲；各數列有包含關係，不應相加。
- SERVER LOG 是原站已成功寫入的紀錄，沒有包含由 Cloudflare 快取直接回覆或被攔截的請求；未寫入、過期刪除的資料也無法查回。
- 點擊預約／開啟預約平台不等於完成預約；真正成功事件仍待另一個預約平台接入。前端回報不是可信交易憑證；沒有事件也不能推定沒有預約。
- 大量資料仍需依日期與條件分段。單程序限流在重啟時重設；未來多副本部署需要共享限流儲存。

## 本機驗證

- 20 項測試通過，涵蓋原有內容與 Sitemap、安全路徑、管理權限、游標防竄改／過期、篩選變更、相同時間戳及新請求插入時的穩定翻頁、匯出上限、IP 遮罩及 CSV 公式注入。
- 瀏覽器實際驗證：數量提示、方向鍵切換、圖例開關、下一頁與事件來源明細；本機請求紀錄確認圖表操作沒有新增 API 查詢，下一頁只新增一筆請求。
- 390 × 844 窄螢幕下提示寬 292px，左右及上下都在可視範圍內；這是瀏覽器響應式驗證，並非實體手機測試。
- 實際從瀏覽器下載本機測試 CSV：177 筆、15 欄，確認完整測試 IP 不在檔案內。測試資料與下載檔均未寫入正式資料庫或專案。
- 本機記憶體資料庫以 100,000 筆測試：首查約 7.38ms、下一頁約 0.43ms、50 筆 JSON 約 16.6KB；這是本機合成資料結果，不代表 Railway 正式站延遲。

## 新增 API

- GET /api/analytics/dashboard：合併摘要、趨勢、爬蟲、互動與限制資訊。
- GET /api/analytics/requests/page：簽章游標、總數、截止時間與 50 筆紀錄。
- GET /api/analytics/requests/export：受限、遮罩、串流 CSV。
- GET /api/analytics/events/details：指定事件的來源頁面與最近活動。

不需要新增 Railway 環境變數；原本管理登入、資料庫 Volume、IP 信任條件及資料保存設定沿用。
